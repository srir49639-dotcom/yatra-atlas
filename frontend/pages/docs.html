FEATURE: Route Finder

PROBLEM: Find the shortest, fastest, or most economical route between any two cities or historical landmarks in India.

ALGORITHM: Dijkstra's Shortest Path Algorithm (Indexed Binary Min-Heap).

WHY: The national transit network consists of positive, non-negative weighted edges (distance in km, transit duration in minutes, fare in INR). Dijkstra with an indexed binary min-heap guarantees the globally optimal shortest path in $O((V + E) \log V)$ time, avoiding Bellman-Ford's $O(V \cdot E)$ overhead.

RESULT: The customer receives the exact step-by-step route (e.g. Charminar ➔ Salar Jung ➔ Golconda Fort), total travel distance, estimated travel time, and fare.

FEATURE: Multi-City Trip Planner

PROBLEM: Given an origin city and $N$ selected tourist destinations, determine the optimal tour sequence that minimizes total travel distance.

ALGORITHM: Held-Karp Bitmask Dynamic Programming for the Travelling Salesperson Problem (TSP).

WHY: Brute force permutation search requires $O(N!)$ time (e.g. $10! = 3.62$ million evaluations). Bitmask DP reduces this complexity to $O(N^2 \cdot 2^N)$ using state compression where integer bitmasks represent visited subsets. This provides exact mathematically optimal tour sequences within milliseconds for $N \le 10$.

RESULT: The customer receives a day-by-day itinerary with cumulative mileage and cost tracking powered by Prefix Sum.

FEATURE: Search & Discovery

PROBLEM: Instantly match keywords (e.g., "fort", "temple", "beach") across thousands of destination descriptions, hotel amenities, and restaurant specialties.

ALGORITHM: Knuth-Morris-Pratt (KMP), Z-Algorithm, and Rabin-Karp via dynamic Strategy Selection.

WHY: Naive pattern searching re-checks characters upon failure ($O(N \times M)$). KMP preprocesses the pattern into a Longest Prefix Suffix ($\pi$) table in $O(M)$ time and skips redundant comparisons, guaranteeing worst-case linear matching in $O(N + M)$. Rabin-Karp uses rolling polynomial hashes for fast multiple substring scans.

RESULT: Near-instant search results across all travel categories with zero perceived latency.

FEATURE: Typo Correction & Fuzzy Search

PROBLEM: Users frequently misspell Indian city and attraction names (e.g. "Charminr", "Hydrabad", "Banglore", "Chenai").

ALGORITHM: Damerau-Levenshtein Distance & Levenshtein Matrix DP.

WHY: Standard Levenshtein treats an adjacent character transposition (e.g., "teh" for "the") as two edits (1 deletion + 1 insertion). Damerau-Levenshtein extends the DP transition matrix to penalize adjacent transpositions as a single edit ($cost = 1$), which aligns precisely with standard typing slip errors on mobile keyboards.

RESULT: User sees friendly suggestions like "Did you mean Hyderabad?" without exposing algorithm names or distance matrices.

FEATURE: Transportation Network Capacity

PROBLEM: Determine maximum daily passenger seat availability between major Indian metropolitan hubs and find network bottlenecks.

ALGORITHM: Edmonds-Karp Maximum Flow & Minimum-Cut Theorem.

WHY: By using BFS to find augmenting paths in the residual network, Edmonds-Karp prevents infinite loops or non-terminating flows associated with irrational capacities, providing a guaranteed polynomial bound of $O(V \cdot E^2)$. The Min-Cut theorem identifies the exact bottleneck edges restricting corridor throughput.

RESULT: Travelers see passenger capacity ratings and early booking bottleneck advisories.

FEATURE: Travel Network Optimizer

PROBLEM: Identify the minimum set of strategic gateway cities necessary to monitor or provide transit links covering all national routes.

ALGORITHM: Vertex Cover 2-Approximation via Maximal Matching.

WHY: Minimum Vertex Cover is proven to be NP-hard. Finding the exact minimum is computationally intractable for large evolving transit graphs. The Maximal Matching 2-Approximation runs in linear $O(V + E)$ time and guarantees an approximation ratio of at most $2.0 \times$ optimal.

RESULT: Identified strategic hub cities (e.g., Delhi, Hyderabad, Bengaluru, Mumbai) covering all regional corridors.

FEATURE: Random Discovery ("Surprise Me")

PROBLEM: Select an unbiased random travel destination from the catalog on every click.

ALGORITHM: Reservoir Sampling (Algorithm R).

WHY: Reservoir sampling processes data streams in a single pass ($O(N)$) and uses $O(1)$ auxiliary space, ensuring that every element in a stream of unknown or unbounded length has an equal $1/N$ probability of selection.

RESULT: True uniform random destination recommendations generated cleanly on every user request.
